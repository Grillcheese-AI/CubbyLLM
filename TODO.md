## Smaller follow-ups

- [ ] **`ops/vsa.py` reports a Vulkan tier it never calls — DO NOT "FIX" THIS BY DISPATCHING TO IT.** `_detect_backend()` returns `grilly_bridge` when `_bridge.blockcode_bind` exists, but `_load_grilly_ops()` loads grilly's **Python** `BlockCodeOps` and every method dispatches to `self._ops`, so the bridge is detected and never used. **That accident is load-bearing.** grilly ships two functions named `blockcode_bind` with *different semantics*: `BlockCodeOps.bind` is true per-block circular convolution, while `_bridge.blockcode_bind` (GPU shader `shaders/blockcode-bind.glsl` and its numpy fallback) is a one-hot **argmax shift**. The latter scans `if (a[i] > 0.5) hot_a = i`; on a continuous block code every entry is < 0.5 (each block sums to 1 over l slots), so both indices stay 0 and it returns the **identity element, silently, without raising** — corrupting any bundle. Wiring dispatch through the bridge would therefore break the algebra on exactly the superposition case the VM channel needs. Correct action: **rename the label only** (report what actually ran), and leave dispatch alone until grilly's shader implements real convolution — `shaders/fft-bind.glsl` exists and is compiled but has no dispatch function authored. Pinned by `tests/ops/test_vsa.py::test_bind_of_continuous_codes_is_not_the_identity`.
