## Smaller follow-ups

- [ ] **`ops/vsa.py` reports a Vulkan tier it never calls — DO NOT "FIX" THIS BY DISPATCHING TO IT.** `_detect_backend()` returns `grilly_bridge` when `_bridge.blockcode_bind` exists, but `_load_grilly_ops()` loads grilly's **Python** `BlockCodeOps` and every method dispatches to `self._ops`, so the bridge is detected and never used. **That accident is load-bearing.** grilly ships two functions named `blockcode_bind` with *different semantics*: `BlockCodeOps.bind` is true per-block circular convolution, while `_bridge.blockcode_bind` (GPU shader `shaders/blockcode-bind.glsl` and its numpy fallback) is a one-hot **argmax shift**. The latter scans `if (a[i] > 0.5) hot_a = i`; on a continuous block code every entry is < 0.5 (each block sums to 1 over l slots), so both indices stay 0 and it returns the **identity element, silently, without raising** — corrupting any bundle. Wiring dispatch through the bridge would therefore break the algebra on exactly the superposition case the VM channel needs. Correct action: **rename the label only** (report what actually ran), and leave dispatch alone until grilly's shader implements real convolution — `shaders/fft-bind.glsl` exists and is compiled but has no dispatch function authored. Pinned by `tests/ops/test_vsa.py::test_bind_of_continuous_codes_is_not_the_identity`. (Correction 2026-08-02: an earlier version of this item claimed all three tiers computed the same math and suggested dispatching to the bridge. That was wrong and would have silently corrupted results.)
- [ ] **Move cubemind's I-RAVEN block shape to the decided k=80 x l=128 (d=10240).** It runs at k=16 x l=128 = d=2048, 5x under the standardized H-B5 algebra, and multi-entity grid configs plateau at 67-77% against 96-100% for single-entity — a capacity ceiling at 9 bundled objects. Prefer the decided shape over the note's proposed 32x256=8192: it keeps l=128 so codebooks and shaders stay compatible, and preserves the one-algebra property. Expect ~2.2x SNR (crosstalk ~1/sqrt(D)), not the "exponential" gain the note claims. Pair it with SequentialHyperGraph-style cleanup between bundling levels. See H-B4.

- [ ] **Re-check H-C1 (hyper-encoder embedding quality) at real scale.** The toy-scale result used a pure surface-form generator and lost about 0.5 nats versus a static embedding table. A context-conditioned generator, or zip2zip-style composition over the now-decided static core, could flip this — untested at the scale that matters.
- [ ] **Resolve the H-B5 generalization question.** grilly's SVC role-filler binding scheme was built for subject/verb/context triples. Whether it generalizes cleanly to CubbyLLM's actual token/concept binding needs is still open.
