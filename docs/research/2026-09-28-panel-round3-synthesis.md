# Panel round 3, read: what changes in the plan (2026-09-28)

Eight of the strongest models on OpenRouter (`docs/panel_round3.md`: gpt-6-luna-pro, gpt-5.6-terra-pro, claude-opus-5.5, gemini-3.1-pro, glm-5.3-prime, qwen3.8-max-prime, grok-4.7, deepseek-v4-pro; $1.15) were given the system brief, the VM as it is, the harness v0 spec and rounds 1–2. **Model opinions, not findings**; each item below is a change to a spec or a pre-registered test, never a result. Where they agreed, the plan moves; where they split, the split is recorded.

## The one premise they all corrected

**A VM-verified chain is not a correct answer.** The VM checks that a program's hops clear τ; it does not check that the program asked the question the person asked. With a trunk that binds at chance, the class that slips through is a *verified wrong-entity program*: real facts about the wrong thing, passing the value check and the claim check. The "0 spoken wrong" numbers were measured with the host handing lookups to the talk adapter, not with a 450M emitter writing programs; they must not be generalised to the emitter seat (Opus, Grok, Luna, Terra, Gemini).

**The mechanism they converged on: slots, not copies.** The model never carries a name or a number the host could place itself. The emitter writes programs with slots (`query $E1, $R1`); the talk adapter writes sentences with slots (`<V1>`, `<E1>`); the host fills every slot by deterministic operations (a span of the question, the context graph's referent, the VM's returned symbol). "The disposer takes it only if it covers" gets its definition: **every entity slot resolves to a span of the question or a context-graph referent, every entity span of the question is consumed by a slot, and the final hop unbinds the asked role** (Opus's coverage check, Grok's EntitySet/AskedRole invariant, Gemini's pointers). Gate: on reworded history (59% today), spoken-and-correct ≥ 70%, spoken-wrong ≤ 1%, grounded-but-wrong before the host halved, and the residual dominated by extractor misses; kill if wrong-slot errors dominate instead (a binding failure in another costume).

## The harness: v0 → v0.1

Kept by all eight: one owner; the registry as the one door; effect classes at call time; deny by default; signed thresholds never recalibrated at boot; exhaustion as a declared outcome; gate 1 (byte-identical answers) as the kill.

Changed (agreed by five or more):

1. **Store generations, not a lock.** The night writes generation g+1 beside g, never touching g; the harness runs the gate pack against g+1 and swaps a signed manifest atomically; every turn pins one generation for its lifetime and the ledger row names it. Two keys: the owner's (thresholds, gate pack, bars, adapter promotion; offline) and the harness's (generation manifests, only after the owner-signed pack passes). The lock in v0 would stall serving for the night's whole run and leaves the store hashes in the signed config stale after every night.
2. **Speak is an effect, ledger-first, at-most-once.** `intent(turn, reply_hash)` is committed before the bytes leave; `spoken(turn)` after. On restart an intent without a spoken row is never re-spoken: the harness reports the interruption or re-asks. Gate 6 reworded: 0 replies spoken without an intent row, 0 spoken twice, every orphan intent resolved.
3. **Everything that bends a turn goes in its row:** the hormone vector at turn start, the generation id, the context-graph delta, the model and adapter hashes, the decode seed. Replay splits in two: **audit replay** (recorded model outputs + the deterministic host) must be 100%; **regeneration replay** (re-decoding on the Vulkan engine) is measured apart, as a property of the engine. Add the gate: the gate pack at hormone extremes yields the same spoken values (refusals may change, values may not); and hormones may narrow `allowed`, never widen it.
4. **Frames declare their postcondition at creation**, typed, by the host — never chosen after the result. `QUERY` returning an empty array is a return, not a success. A child frame's permissions are the intersection of its parent's and its kind's; a tree, not a DAG, until a gate needs a join.
5. **Budgets include generated tokens** (`gen_tokens`): at ~40 tok/s a copy-emitted program is 60–120 tokens, so wall time is the binding budget and would trip silently inside gate 1. Pre-register that on the gate-1 sets no budget binds. Grok: `fetches: 1` starves refuse → fetch → second walk (two by design).
6. **`propose` needs a quarantine store and one `promote` tool** (effect `write`, gated); `fetch` is an `external` effect, off for fact and chat kinds. Native VM modules reachable through `use` get effect classes in the same registry; the emitter's program may not choose `knowledge_path` or the jump budget — the harness sets both from the frame.
7. **Worlds are namespaces.** Facts carry world id, epistemic status (observed / asserted / hypothetical / counterfactual / derived), valid time and provenance; a counterfactual branch never shares a namespace with observed history; `store.write` is namespaced by world before Cubby-Man grows.
8. **The gate pack rotates** (a small blocking boot pack, a larger offline regression pack, held-out sentinels never used in harvesting), and it must include the real defect: a contradicting context, an absent role, a verified program that answers the wrong role.
9. **The 2.6B stand-in emitter cannot sit on the serve path** beside the 450M on 12 GB (Grok); it is a night teacher. The live emitter is a 450M adapter or it is not in the loop.

## The VM: step 0, before the branch runner trusts a program

Agreed by seven or eight:

1. **An absent role returns Null, structurally** (the role is not among the frame's bindings), with reason `absent_role`; the threshold guards only crosstalk among present roles. Today the absent-role control rests on noise staying below τ: a statistical guard doing a structural job. Gate: absent-role probe Null in 100% of n ≥ 500; present-role false-silence unchanged ±1 point; E8/E9 unchanged.
2. **The 24 trace-only mnemonics become compile errors** until each has semantics and a test; the permission attributes likewise (advertised-and-unenforced is worse than absent). **Measured today (2026-09-28): 0 of 1,209,553 records across every emitter SFT file and the CoT harvest contain one** (`infer`, `analogy`, `debate`, … `unify`), so the harvest is clean; the fix is to keep it so.
3. **Budgets on the request**, set by the harness from the frame: jumps (done today, `Branch.max_jumps`; live default to be the harvest's p99.9 × 10, measured first — Opus estimates real chain programs under 1,000), instructions, queries, array size, VM wall. 1,000,000 jumps is not a budget for a live turn.
4. **The branch report** carries the runner-up similarity and margin per hop, a closed reason enum, the read set tagged base / assumed / contingent, `assumption_used`, and the overlay echoed back as applied (done today: `excluded_keys`).
5. **ASK is prohibited inside branch programs** for v1 (resume re-executes from scratch; the host resolves ambiguity before branching).
6. **Call frames: not now** (six of eight); needed only if the turn becomes a program or ASK must live inside CALL. Gemini and Terra want them first.
7. **The harvest needs a correctness gate, not only a verification gate:** keep only programs whose answer matched gold or the host's independent check and whose slots passed coverage; report the family distribution nightly.

## The branch runner (D)

All eight: **wire-level first; `ctx.fork` is not the prerequisite** (rounds 1–2 were wrong there). Built today: `Branch{exclude, assume, max_jumps}` on the RunRequest, applied to that request's own clone; `BranchReport{ops, jumps, queried, excluded_keys, assumed, max_jumps}` on every result; `VM::snapshot/restore` as methods for a later in-VM fork. Two additions before the gate:

- **Closure-aware overlays** (Opus): excluding event E leaves E's consequences in the store, so a branch can "verify" a counterfactual by reading a fact that exists only because E happened. The host computes E's downstream closure over the causal links to depth k and marks those facts **contingent** (not deleted: some effects have other causes); a read of one is a tainted read; a branch whose answer depends on one gets verdict `contingent`, spoken as "if X hadn't happened, Y might not have either; the facts don't say what would have followed". Report the closure size; hand-check 50.
- **`assumption_used`**: a branch whose outcome never touched its own counterfactual is uninformative and is not presented as a counterfactual answer. Opus's guess: this catches much of today's 18% that is "correct" for the wrong reason.
- **The host steers, not the model** (Opus, Grok): feeding a report back into the model's context and expecting it to condition on it is the capability measured at 22/24. The emitter's next context gets an outcome code and the symbol, never a page of fact ids (which copy loss 1.2 would paste into the next program). Model steering becomes a candidate only when a report-sensitivity probe clears 85%.
- **Localise first** (Grok): instrument the current 18% path and count which store the walk reads (history-graph edge ids, wiki QUERY keys, or hippocampal RECALL); the overlay keys are whatever it reads, and RECALL must not be used for counterfactuals (cleanup fails open).
- Gate: reworded counterfactual 18% → ≥ 40–50%, spoken-wrong ≤ 1%, 100% of spoken counterfactuals with `assumption_used`, 0 cross-branch leakage, exhaustion declared. Kill: lifting spoken-correct requires relaxing `assumption_used`.

## The turn stays Python; CubeLang is the proof tool

Eight of eight. The judge must not be the actor; ASK-resume re-executes from scratch, so a turn with side effects cannot be replayed idempotently; the emitter's learnable surface is one program per host-enumerated branch, never the orchestrator. Keep the ASK contract for clarifying questions inside branch programs. Serialise the Python turn's trace as a typed, CubeLang-shaped record so a later port has a corpus to reproduce.

## Fluency at 450M: host-side first, the chat guard is a mask, measure before training

- **The form feel is three host choices**, not a weight deficit (Opus): the adapter sees only the canonical restatement; the value check allows one value; three moves. Cheapest fluency: give the talk adapter the person's words as style context (marked, kept out of the fact slots), multi-slot answers with a per-slot check ("I don't have the cause; it was 1683" is an absent slot and a value slot), a fourth move (acknowledge and redirect). Gate: ≥ 65% blind preference on 200 paired turns, 0 wrong spoken, guard-reject rate within +3 points.
- **The sanctioned-set guard as a sentence was the panels' hole.** A name-and-number set does not constrain relations, polarity, time or causality ("Lyon is the capital of France" passes). Chat may name no entity and no number outside the person's current turn and may make no copular or relational claim between two entities; anything factual routes through the fact path. Enforce it as a **decode mask** over the 128k BBPE (the sanctioned surface forms and inflections, both languages, at entity positions), not a post-hoc filter that hides a 30% violation rate behind "0 spoken wrong"; report the leakage through sub-word pieces.
- **Measure first:** the chat guard's pass rate on 500 real conversational turns (estimates: 40–75%); below ~70% the chat path mostly refuses and the chat adapter is not built. Then the round-1 diagnostic (fact-only / chat-only / mixed at equal tokens). Router fact-class recall ≥ 99% on 500 turns, measured, before any chat adapter.
- **Continued pretraining may strengthen parametric memory** (Grok): run the contradicting-context probe at n = 200 before and after; the new base hash enters the signed config only if the override rate does not rise by more than 5 points. GLM: the untied 128k head is 262M of 576M at 2.77B tokens; tie or factorise it as one ablation during the continuation.

## The HDC memory: diagnostics first, data before architecture

Seven of eight would not run the layer next. Before any architecture: (1) the **binding-vs-distance curve** (if binding is fine within 512 tokens and collapses beyond, the deficit is architectural and an associative memory is the right fix; if ~52% at every distance, it is data); check whether 52% is chance for a two-way probe; (2) the binding probe at every continuation checkpoint; (3) **synthetic binding and override passages at 5–10% of the continuation** (entity–attribute tables with shuffled values, contexts contradicting world knowledge), an arm at equal tokens against the plain continuation, gate: binding ≥ 85%, memory-over-context 22/24 → ≤ 6/24, held-out cost ≤ 0.02 nats. GLM's alternative aim: the **emitter's** binding, with a synthetic role-binding curriculum (~50k VM-verified programs) — and first measure the emitter's compile-and-verify rate on held-out binding programs, which nobody has. If the curve is distance-dependent, run the HDC layer only against an extra-attention-layer arm at equal parameters (Opus), winning on binding beyond 512 within 0.02 nats; kill if the gate stays below 0.05.

## The order, as it stands after round 3

0. **VM step 0** (days): Null for an absent role; trace-only mnemonics and permission attributes as compile errors; budgets on the request (jumps done); runner-up similarity; the harvest correctness gate.
1. **Harness v0.1** (the nine changes above); first gate = refuse-to-serve + ledger-first speak + deny probes (≥ 500, not 50) + the absent-role probe; gate 1 stays the compatibility kill.
2. **Slot programs and the coverage check** on the current ask path (gate: reworded history +10 points, entity-set invariant 100%, spoken-wrong ≤ 1%).
3. **Wire-level branch runner** with closure-aware overlays, `assumption_used`, host steering (gate above).
4. **Binding diagnostics, then data** (the synthetic arm in the continuation); HDC only on a distance-dependent curve.
5. **Fluency host-side**, then the chat mask measurement, then a chat adapter only if ≥ 70% of drafts pass the strict guard.
6. Report-conditioned emission only after the report-sensitivity probe clears 85%; in-VM `ctx.fork` only when a gate needs within-program backtracking.

Disagreements left open: Gemini and Terra want call frames and an HDC experiment earlier; DeepSeek wants the task DAG before the branch runner; Qwen would fine-tune the emitter weekly rather than nightly (a promotion cadence, not a mechanism change). None changes step 0 or step 1.

## Addendum, 2026-09-29: VM step 0 built

The order's item 0, done in cubelang (`docs/STEP0.md` there; `tests/vm_step0.rs`, `tests/recover_scope.rs`; 366 Rust tests pass) and wired through `cubbyllm/bridges/cubelang_client.py` (`tests/bridges/test_cubelang_step0.py`; 149 bridge + reasoning tests pass):

1. **Absent role → Null, structurally.** The frame records its roles; `recover` of a role not among them returns Null with reason `absent_role` before any unbind, so no similarity exists to threshold. Gate met: absent-role probe **500/500 Null**, present-role recovery **500/500**, the genuine 3-role number unchanged (0.27001953125 against tau_vm(3) = 0.22021484375). The chain verifier's control (`ABSENT_CTRL`) now passes on the reason, not on sitting below tau; a control that recovers anything, or is Null for another reason, is named in the failure (`control:<reason>`).
2. **Attributes.** The 24 trace-only mnemonics were already strict errors on the serve path; now `@hook/@before/@after/@cron` are too (parsed, never enforced), while `@internal`/`@system` are refused as the host's entry and `@once` refuses a second run. The harvest is unaffected: every program marks `solve` `@external` and the constructor `@system @once`, both honoured.
3. **Budgets on the request.** `Budget{max_jumps, max_ops, max_queries, max_wall_ms}` on the RunRequest, each refused by name before the step that would cross it; the report echoes the budget and the wall clock spent. The live defaults (the harvest's p99.9 × 10) are still to be measured; the harness sets them from the frame.
4. **The report.** Every recover hop with winner, similarity, runner-up, margin, pool and a closed reason; `runner_up` and `recover_reason` beside `similarity` on the result. `HopTrace.runner_up` is filled and logged, not yet gated: the margin gate is a threshold to calibrate, not to guess.
5. **The harvest correctness gate** (`standin/data/build_emitter_sft.py`): a chain enters the emitter SFT set only when verified AND correct against gold (or the host's independent check) AND every literal it binds occurs in the prompt. Measured on `cot_harvest_v3cf`: 517 verified → 513 kept; **4 verified-but-wrong removed** (0.77%, the precision-0.9923 residue), 0 uncovered (the v3 prompt carries the walked facts). The manifest now reports the family distribution with each family's gate named (role-binding is executes-only and says so).

Not done: call frames (the panel's "not now"), the read set tagged base/assumed/contingent and `assumption_used` (the branch runner's own step), the array-size budget.
